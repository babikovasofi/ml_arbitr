# ml_arbitr — поставка локальной модели «Арбитра», v0.3

Здесь лежит всё, что относится к раскладке модели для мобильного приложения: манифест,
промпты, грамматики и инструкция по заливке. **Весов (`.gguf`) здесь нет** — GitHub не
принимает файлы больше 100 МБ, а они и не изменились, см. ниже.

## Коротко для тимлида

**Веса перезаливать не нужно.** В версии v0.3 обе модели байт в байт совпадают с v0.2:

| Файл | Размер | sha256 |
|---|---|---|
| `qwen3.5-2b-q4_k_m.gguf` | 1 280 835 840 | `aaf42c8b7c3cab2b…` |
| `qwen3.5-0.8b-q4_k_m.gguf` | 532 517 120 | `bd258782e35f7f45…` |

Полные суммы — в [`runtime_v0.3/manifest.json`](runtime_v0.3/manifest.json).

Если в бакете уже лежат файлы с такими же суммами — делать не нужно ничего.

## Что изменилось в v0.3

1. **Новый промпт** `resources/prompts/score_level_hints.txt` — по нему оцениваются критерии
   с подкритериями.
2. **Требования к железу в манифесте** — у каждого варианта появились `min_free_ram_mb`,
   `recommended_free_ram_mb`, `min_cpu_cores`.
3. Версия в пути — `v0.3`.

## Важно: как приложение на самом деле забирает файлы

Приложение **не ходит в бакет напрямую**. Оно запрашивает у бэкенда:

```
GET /download/{имя файла}
```

Бэкенд (`go_api/internal/download/service.go`) читает объект по ключу `models/{имя файла}`
в своём бакете и **отклоняет имена со слэшами** — вложенные пути через этот эндпоинт
недоступны.

Из этого следует:

- раскладка вида `arbitr/models/v0.3/qwen3.5-2b/qwen3.5-2b-q4_k_m.gguf` приложению
  **не видна**;
- файлы весов должны лежать **плоско**: `models/qwen3.5-2b-q4_k_m.gguf` и
  `models/qwen3.5-0.8b-q4_k_m.gguf` в том бакете, который задан бэкенду через `S3_BUCKET`;
- `resources/prompts/*` через этот эндпоинт скачать нельзя вообще.

**Вопрос, с которого стоит начать:** в какой бакет и по какому ключу смотрит `/download`.
Пока на него нет ответа, любая заливка может не дойти до устройств.

## Промпты едут в сборке приложения

Приложение читает промпты и грамматики из своих ассетов (`assets/model/`), а не из
скачанного каталога. Файлы в [`runtime_v0.3/resources/`](runtime_v0.3/resources) —
эталон: те же самые уже добавлены в мобильный репозиторий, ветка
`feature/scoring-coverage-scale`.

Менять их в приложении отдельно от весов нельзя: промпты, грамматики и веса версионируются
вместе.

## Где лежит полный каталог с весами

Собирается одной командой из репозитория `arbitrator_ml`:

```bash
uv run python local_model/scripts/build_handoff.py --layout runtime --version v0.3 \
    --base-url https://storage.yandexcloud.net/arbitratorbucket1/arbitr/models/v0.3/
```

Результат — `dist/arbitr_runtime_v0.3/`, 1.8 ГБ. Сами веса скачиваются с Hugging Face
скриптом `local_model/scripts/download_models.py`.
